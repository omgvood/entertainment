# Полнота афиши Перми на 2026-09-26 (суббота)

Тикет: `docs/superpowers/wayfinder/p2-data-fixes/issues/16-afisha-recall.md`

## Question

Сколько событий города Пермь на конкретную субботу (2026-09-26) наша выдача не находит по сравнению с независимыми внешними афишами? Что реально лежит в `coverage_stats`?

## Method

1. Наша выдача — Supabase MCP, project `taixlqbbepudndqhnehj`:
   `select title, venue_name, type, source, source_url from events where city='perm' and date='2026-09-26' order by title;`
2. Внешние афиши — три независимых источника (без KudaGo, по опыту проекта данных по Перми там нет):
   - `59.ru/afisha` (сетевое издание, дата-фильтр по URL `?startedAtGte=YYYY-MM-DD` для категорий concert-events/theatre-events, общий фид афиши на главной странице `/afisha/`);
   - `gorodzovet.ru` (агрегатор мероприятий, календарь по датам);
   - `afisha.ru/prm/` + веб-поиск (сниппеты по «афиша Перми 26 сентября 2026», использованы как кросс-проверка, т.к. сам сайт date-фильтр по URL не принял).
3. Сопоставление вручную по заголовку/площадке/времени.
4. `coverage_stats` — `select * from coverage_stats order by snapshot_date desc limit 50;` + `list_tables` (verbose) для структуры колонок.
5. `parser/config/seeds.yaml` — проверка, есть ли источники под потерянные площадки; `candidate_sources` — `select domain, status, score, has_jsonld_event, last_verified from candidate_sources where city='perm' order by status, domain;`

### 5. `coverage_stats`

Структура (`list_tables`, verbose): `city text, category text, count integer, snapshot_date date`, PK `(city, category, snapshot_date)`. Строк всего 2027.

Содержимое — это ежедневный срез **суммарного количества событий в БД по категории** на момент снятия снимка (`snapshot_date` = дата снятия, не дата события), не привязан к конкретному дню афиши и не сравнивается с внешним источником истины. Например, snapshot `2026-09-21`: `perm/exhibition=87`, `perm/concert=74`, `perm/theater=29`, `perm/kids=28`, `perm/sport=21` и т.д. — это просто «сколько карточек каждого типа сейчас лежит в базе для города», без разбивки по датам событий и без понятия «сколько должно быть». Таблица подтверждает наблюдение из тикета: `coverage_stats` не измеряет recall (полноту относительно внешнего мира), а только объём уже спарсенного — метрика полноты, которую просит тикет, в БД действительно отсутствует.

## Локализация

Локализация: `select ... from events where city='perm' and date='2026-09-26'`, `select * from coverage_stats order by snapshot_date desc limit 50`, `list_tables(verbose=true)`, `select domain,status,score,has_jsonld_event,last_verified from candidate_sources where city='perm'` (Supabase MCP, project `taixlqbbepudndqhnehj`); просмотр `parser/config/seeds.yaml`; браузер — `https://59.ru/afisha/` + `/afisha/concert-events/?startedAtGte=2026-09-26` + `/afisha/theatre-events/?startedAtGte=2026-09-26`, `https://gorodzovet.ru/perm/`, `https://www.afisha.ru/prm/`, веб-поиск «афиша Перми 26 сентября 2026 суббота куда сходить» и «properm.ru афиша 26 сентября» (properm.ru/afisha/ — 404, раздел афиши на сайте больше не существует). Найдено 23 уникальных внешних события за 26.09, 4 совпадения, 10+ конкретных потерянных площадок с указанием, есть ли под них источник.

## Вывод

Recall по одной проверенной субботе ≈ 17% (4 из 23 уникальных внешних событий). Провал системный, а не единичный: ни одно совпадение не пришло через профильные источники площадок (filarmonia/teatr-teatr/permm/permopera) — все 4 совпадения дал `vk-posts`/`permkudapoiti`. Основные потерянные площадки — драматические/кукольные театры (Театр кукол, Театр «У Моста», Молодёжный театр, ДК железнодорожников и др.) и часть филармонии — ни у одной из них, кроме `teatr-teatr.com` и `filarmonia.online`, нет источника в `parser/config/seeds.yaml` или одобренного домена в `candidate_sources`; там, где источник есть и подключён (filarmonia), конкретное событие всё равно не попало — стоит отдельно разобраться, почему.

Рекомендация: **добавлять источники**, а не считать выдачу достаточной для P2 — recall 17% слишком низкий, чтобы полагаться на чипы-сценарии поверх будничных/выходных дней. Приоритет: (1) одобрить `teatr-umosta.ru` в `candidate_sources` и проверить, почему `has_jsonld_event=false`; (2) добавить домены Театра кукол и Пермского Молодёжного театра в discovery/candidate_sources вручную (сейчас их там нет вообще); (3) разобраться, почему `filarmonia.online` (approved, JSON-LD есть) не приносит конкретно эту симфонию — баг существующего источника, а не отсутствие источника; (4) рассмотреть одобрение `59.ru` и `gorodzovet.ru` как generic-кандидатов — оба уже обнаружены системой, но не одобрены.
