# Протокол сессии

Правила о том, как ведётся работа. Что делать в конкретной задаче — в тикете; какой скилл брать — в `skills-routing.md`.

Разбор инцидентов, из которых эти правила выросли, — в Obsidian, `Projects/entertainment/Журнал проблем.md`. Журнал в сессию не подаётся, поэтому правило, живущее только там, не действует: всё действующее лежит здесь или в `CLAUDE.md`.

## R-01. Сверка состояния — до всего остального

Перед исследованием, планированием и первой правкой:

```
git log --oneline origin/master..master
git status -sb
git worktree list
```

Карта, тикет или отчёт, построенные от `origin/master`, врут, если локальный `master` ушёл вперёд.

**Сломалось, если:** цифры в задаче не сходятся с репозиторием или БД; тикет описывает работу, которая уже в `master`.

## R-04. Ветка и worktree живут ровно до мерджа

Уборка — **шаг закрытия сессии, а не команда git.** Мердж часто происходит кнопкой на GitHub, вне сессии-владельца worktree, поэтому «после мерджа приберись» само не срабатывает.

Порядок после слияния PR:

1. Закрыть сессию/вкладку, которая держит worktree — иначе `git worktree remove` падает с `Device or resource busy`.
2. `git worktree remove <путь>`
3. `git branch -d <ветка>`
4. `git pull --ff-only` в основном чекауте — мердж-коммит с GitHub сам туда не приходит.

Worktree, в котором не оказалось работы, убирается так же — мерджа ждать не нужно.

Уборка нужна не только после мерджа. Claude Code заводит ветку `claude/<имя>-<hex>` от `origin/master` и worktree под неё **в момент старта сессии**, независимо от того, сделает сессия работу или нет. Сессия, которая ничего не закоммитила, оставляет такой worktree навсегда: мерджа не будет, значит и триггер «после мерджа» не наступит. За 2026-09-20 так накопилось три штуки.

Проверка автоматическая: `scripts/process-check.ps1 -Mode stop` висит на Stop-хуке и при закрытии сессии называет worktree без коммитов и ветки, пережившие мердж. Worktree с незакоммиченными изменениями считается живым и не называется. Одна и та же находка называется сессии один раз — повторяющееся слово в слово замечание перестают читать. Хук не убирает ничего сам: он не даёт пропустить уборку молча.

**Сломалось, если:** `git worktree list` показывает запись без открытого тикета в волне; `git worktree remove` падает с `Device or resource busy`.

## R-05. Три открытых задачи, детализация на одну волну вперёд

Одновременно открыто не больше трёх тикетов: одна блокирующая плюс две дешёвые параллельные. Остальное живёт одной строкой в тумане карты и расписывается, когда до него дойдёт очередь.

Между отчётом с находками и тикетами обязателен шаг **сведения**: один экран, три-семь проблем, у каждой строка «что не так» и метка (блокирует остальное / дёшево и независимо / дорого и спорно). Человек выбирает волну. Без этого шага тикеты писать нельзя.

**Сломалось, если:** тикетов со `Status: open` без `## Answer` в активном эффорте больше трёх (`Status: backlog` не считается — иначе признак срабатывает на всём бэклоге и перестаёт что-либо различать); «не понимаю, с чего начать»; задача переписана второй раз до того, как до неё дошли руки.

## R-06. Названные пути существуют

Любой путь, упомянутый в `CLAUDE.md`, `skills-routing.md` или этом файле, обязан существовать на диске и быть трекаемым. `CLAUDE.md` месяцами ссылался на `.scratch/`, которого никогда не было, — расхождение было молчаливым.

`docs/` — ровно четыре папки: `agents/`, `superpowers/`, `research/`, `personal/` (не трекается). Файл, попавший в `docs/` мимо них, git не увидит — это сигнал, что он не на своём месте.

**Сломалось, если:** путь из этих файлов не открывается; в `docs/` появился файл вне четырёх папок.

## Аудит в конце волны

После закрытия волны, до нового сведения: пройти по «Сломалось, если» всех правил здесь и в `CLAUDE.md`, обновить счётчик повторов в реестре журнала.

Решение по счётчику, а не по ощущению: 0 повторов за три волны — правило закрывается; 1 — уточняется формулировка; 2 — правило **поднимается уровнем** (этот файл → `CLAUDE.md` → хук), текст не переписывается.
