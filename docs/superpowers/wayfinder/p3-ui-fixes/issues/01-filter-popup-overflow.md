# FilterBar: попапы обрезаются overflow корневого контейнера

Type: task
Скилл: verification-before-completion — критерий готовности проверяется вручную в браузере на трёх ширинах, юнит-тестом CSS overflow не проверить
Status: закрыт
Blocked by: —
Ветка: `fix/filter-popup-overflow`

## Question

Оба попапа FilterBar — «Ещё N ▾» (типы) и «Ещё фильтры ▾» (цена) — не видны пользователю при клике на 1280px, хотя рендерятся в DOM (`aria-expanded=true`).

Root cause (verified, `HANDOFF_FilterBar_zIndex_Issue.md` + независимая проверка в браузере 2026-09-20): оба попапа — `position: absolute` потомки корневого `<div>` `FilterBar.tsx:41`, на котором висит `md:overflow-x-auto`. По CSS 2.1 (§11.1.1) если `overflow-x` не `visible`, а `overflow-y` явно не задан, браузер вычисляет `overflow-y` тоже как `auto` — computed style корня на 1280px: `overflow-x: auto; overflow-y: auto`. `overflow: auto` на предке клипует потомка независимо от `position: absolute` и `z-index`.

Замер в браузере (1280px, `Ещё 14`): попап `bottom: 628.875` при границе корня `bottom: 275.25` — обрезка ~350px, попап невидим целиком. Тот же замер для «Ещё фильтры»: попап `bottom: 394.3`, граница корня та же `275.25` — обрезка ~119px.

**Расхождение с первой версией тикета:** здесь ранее было написано, что «Ещё фильтры» не страдает, т.к. его родитель без `overflow` — неверно, единственный `overflow`-предок у FilterBar один и тот же корневой `<div>`, оба попапа его потомки. Обнаружено и исправлено 2026-09-20 при независимой проверке root cause (Phase 1 systematic-debugging).

Три попытки фикса без выноса попапа из-под родителя не сработали (см. handoff, раздел «Failed Attempts»): удаление `overflow-x-auto` ломает горизонтальный скролл чипов на десктопе; произвольные Tailwind-классы и inline-style `overflowY: visible` браузер приводит обратно к `auto`; `!important` в `globals.css` не действует, пока попап остаётся потомком overflow-контейнера.

## Готово когда

- Оба попапа («Ещё N ▾» и «Ещё фильтры ▾») полностью видны при клике на 1280px (desktop), 768px (tablet) и 375px (mobile).
- Горизонтальный скролл чипов типов на десктопе не сломан.
- `npm run dev` → открыть `FilterBar` → нажать «Ещё N» → попап виден полностью, без обрезания; то же для «Ещё фильтры».

## Решение

Option A из handoff, расширенный на оба попапа: разделить корневой `<div>` (строка 41) на внешнюю обёртку (`position: relative`, без `overflow`) и внутреннюю обёртку только вокруг горизонтально скроллящегося контента (поиск, разделитель, чипы типов, кнопка «Ещё фильтры»), на которую переносится `md:overflow-x-auto`. Оба попапа рендерятся как прямые потомки внешней обёртки — вне зоны `overflow`.

- Попап «Ещё фильтры» (`right-0 top-[calc(100%+8px)]`) уже был позиционирован относительно всего бара — при переносе на уровень внешней обёртки классы не меняются, поведение идентично сегодняшнему.
- Попап типов был позиционирован относительно `relative`-контейнера чипов (строка 69), который остаётся внутри скроллящейся внутренней обёртки. При переносе наружу нужна явная позиция: `ref` на кнопку «Ещё N» + `ref` на внешнюю обёртку, координаты вычисляются в момент открытия (`getBoundingClientRect`).
- Известное ограничение: если пользователь прокрутит чипы типов по горизонтали **пока попап открыт**, позиция попапа не пересчитается (пересчёт только при открытии). Это не регресс — сегодня попап в этом сценарии невидим в принципе.

Отклонено:
- Option B (React Portal) — лишняя зависимость и сложность позиционирования без явной необходимости.
- Option C (CSS override `overflow-y: visible` на предке) — уже проверено в предыдущей сессии, не работает, пока попап остаётся потомком overflow-контейнера.

## Answer

Реализовано Option A, расширенный на оба попапа: корневой `<div>` `FilterBar.tsx` разделён на внешнюю обёртку (`ref={barRef}`, `position: relative`, без `overflow`) и внутреннюю обёртку (`display: contents` на mobile, `flex md:overflow-x-auto md:flex-1 md:min-w-0` на десктопе) вокруг горизонтально скроллящегося контента. Оба попапа (`moreTypesOpen`, `moreOpen`) вынесены прямыми потомками внешней обёртки.

- Попап «Ещё фильтры» перенесён без изменения классов (`right-0 top-[calc(100%+8px)]` относительно внешней обёртки — идентично старому поведению).
- Попап типов получил явное позиционирование: `ref={moreTypesBtnRef}` на кнопку + `getBoundingClientRect()` кнопки и `barRef` в момент клика (`toggleMoreTypes`), координаты — `style={{ top, left }}`.

Верификация (`superpowers:verification-before-completion`): `npx tsc --noEmit` чист. Визуальная проверка в браузере на 1280/768/375px через временный изолированный маршрут `web/app/dev-preview-filterbar/page.tsx` (мок-данные, `FilterBar` напрямую, без Supabase) — реальная страница `/perm` была недоступна из песочницы из-за нестабильного сетевого соединения до Supabase (`ECONNRESET`, внешняя причина, не связано с правкой; 4 попытки подряд). Маршрут-заглушка удалён после проверки, в git не коммитился.

Результат на всех трёх ширинах: оба попапа видны полностью, без обрезания; горизонтальный скролл чипов на 768px сохранён (полоса прокрутки видна, поле поиска частично уезжает за левый край при скролле — ожидаемо).

Локализация: грепом `moreTypesOpen|overflow` по `web/`, найдено 5 мест (`FilterBar.tsx` × 4, `CityView.tsx` — потребитель); правка коснулась только `FilterBar.tsx`.
