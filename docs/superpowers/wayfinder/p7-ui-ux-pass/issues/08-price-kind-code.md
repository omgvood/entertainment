## Question

Две связанные проблемы:

1. **Решение p2 «Цена в схеме» не реализовано.** Решение принято 2026-09-22 (карта p2, тикет 08, «Код — отдельным тикетом»), тикет не заведён. Вид цены по-прежнему выводится регулярным выражением `priceKind()` в `web/lib/price.ts`, колонки `price_kind` нет.
2. **Подписи цены разнобойные.** На карточках `/perm` 2026-09-22: «0 ₽», «Бесплатно», «по билетам», «билеты», «Покупка билетов», «от 500 ₽». Это сырой `price_text` от LLM. По решению p2/01 «0 ₽» означает «цену не знаем», но на карточке пользователь видит «0 ₽».

Предложение из UX-разбора (подтвердить в сессии): три вида подписи — «Бесплатно», «от N ₽», и одна подпись для неизвестной цены, например «Цена на сайте».

## Контекст

- Решение: `docs/superpowers/wayfinder/p2-data-fixes/issues/08-price-unknown-in-schema.md`, `## Answer`. Кратко: enum-колонка `price_kind` (`known`/`free`/`unknown`, `NOT NULL DEFAULT 'unknown'`); LLM пишет `free` только при дословном «бесплатно»/«вход свободный»; бэкфилл — `unknown` для всех старых строк; `priceKind()` читает колонку. Не проверено: надёжность `free` у `jsonld`/`timepad` (цена `0` в `offers`).
- Факты под решением — p2, тикет «Проверка «бесплатно» по источникам»: `price_text` как признак «бесплатно» ошибается в 46% проверенных.
- `README.md` п. 18 «Разделить «бесплатно» и «цена неизвестна»» описывает старый вариант (`price_unknown boolean`) — обновить под `price_kind`.
- `README.md` п. 12 «Функциональный поиск», фаза 2 — разблокируется этим тикетом.
- Работа в трёх слоях: миграция Supabase (запись — только с согласия пользователя, правило карты p2), парсер (промпт, модели, валидатор), фронт (`price.ts`, `EventCard`, фильтр цены). **Если не влезает в одну сессию — разделить** на «миграция + парсер» и «фронт + подписи».
- Цена поверх заглушки (решение p2 «Карточка без картинки», вариант D) берёт ту же подпись — при смене подписей меняется и она.
