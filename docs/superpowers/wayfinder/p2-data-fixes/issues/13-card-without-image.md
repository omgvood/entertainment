## Question

Картинки нет у 43% событий (155 из 359; у VK — у 64% событий, 143 из 225). Быстрый просмотр строится вокруг картинки, поэтому нужно увидеть, как выглядит лента, где почти половина карточек без неё.

## Контекст

- Сейчас на месте картинки рисуется плейсхолдер по типу (`web/lib/event-styles.ts`, `CardImage.tsx`) — визуально это большой пустой блок 16:9.
- У 64 событий нет описания, у 37 нет ни картинки, ни описания.
- Варианты для сравнения: плотная текстовая карточка без блока картинки; общий плейсхолдер как сейчас; смешанная сетка, где карточки без картинки ниже.
- Прототип черновой и одноразовый: его задача — дать повод для решения, а не попасть в продакшен.

## Готово когда

Есть черновой прототип (можно статической страницей на реальных данных из БД), пользователь на него посмотрел и выбран вариант. Решение записывается в ответ и питает тикет 07.

## Answer

Локализация: `grep -r "event-styles\|CardImage" web/`, `grep -r "imageUrl" web/` → найдено 5 + 11 мест (пересечение: `CardImage.tsx`, `EventCard.tsx`); реальный потребитель плейсхолдера — только `EventCard.tsx` → `CardImage.tsx`, единая сборка сетки — `CityView.tsx` (`SeriesGrid`/`DaySection`/`SearchResults`).

Прототип на ветке `proto/card-without-image` (не мерджится, коммиты `b141dcf`, `8982dc9`, `8cd9ff3`, `b094b19`), переключатель `?cardVariant=A|B|C|D` на живой ленте `/perm/`, `/sochi/`, четыре варианта:

- **A** — текущее поведение (плейсхолдер-градиент по типу, без изменений).
- **B** — для карточек без картинки блок картинки не рисуется вовсе, плотная текстовая карточка. Отклонён пользователем: «выглядит пусто».
- **C** — картинка как в A, но карточки без неё в пределах дня уходят в конец сетки. Отклонён пользователем: «скрываем, а не решаем проблему».
- **D — выбран.** Слот картинки и порядок сетки остаются как в A (ничего не прячется, не переставляется), но вместо голой эмодзи на градиенте — цена (`event.priceText`) поверх плейсхолдера, в полупрозрачной плашке снизу по центру. Плейсхолдер несёт факт вместо пустоты.

Перед тем как строить D, проверил в БД альтернативу «фото площадки вместо плейсхолдера» (`execute_sql` на `events`/`venues`, город Пермь, будущие события): не годится сейчас — 0 из 132 событий без своей картинки имеют площадку с фото, в `venues.image_url` вообще нет данных ни в Перми (0/27), ни в Сочи (0/40). Это дыра в источниках фото площадок, отдельная задача, не решается в рамках 13.

Для тикета 07 (быстрая карточка) реализация — в `web/components/EventCard.tsx` на ветке-прототипе: `richPlaceholder = !isUsableImage(event.imageUrl)` → вместо `CardImage` рендерится тот же `placeholder.gradient` + `placeholder.emoji`, плюс плашка с `event.priceText` (обрезка `line-clamp-1` — `priceText` не нормализован по длине, встречаются варианты вроде «по билетам», «вход свободный»). Сортировку в `CityView.tsx`/`SeriesGrid` трогать не нужно — порядок как сейчас.

Второстепенная находка при проверке (не блокирует решение): в `CityView.tsx` при чтении `cardVariant` из URL на монтировании список допустимых значений не синхронизировался с `CARD_VARIANTS` при добавлении `D` — пришлось руками дописать `"D"` в условие. Если 07 унаследует этот паттерн чтения варианта из URL, стоит держать список в одном месте, а не дублировать.
