# Группы типов и формат URL

Type: grilling
Скилл: superpowers:brainstorming — решение меняет URL и набор чипов, нужны варианты с ценой ошибки
Status: resolved
Blocked by: —

## Question

18 чипов типов заменяются на 6–8 групп. Решить две вещи: состав групп и что при этом пишется в URL, чтобы не поломать состояние, которое вводит P1.

## Контекст

- В `EventType` 22 значения (не 18), в будущих событиях Перми встречаются 18. `bowling`, `billiards`, `karting`, `quest` — ноль: эти места живут в `venues`.
- Черновик из исследования (события / серии, Пермь, 435 на 19.09): Музеи и выставки 93/58, Музыка 79/73, Лекции и мастер-классы 73/64, Театр и кино 44/36, Квизы, стендап, вечеринки 33/28, Спорт и прогулки 28/24, Фестивали и праздники 23/19, Детям (тип) 25/19, other 37/32.
- «Детям» по типу — 25 событий, по тегу ∪ типу — 82. Предложение исследования: не группа, а чип-аудитория.
- `other` предлагается убрать из чипов; после тикета 03 там 25 событий.
- В `master` уже есть `web/lib/urlState.ts`: пишет `type=concert,theater` и отбрасывает неизвестные значения. Варианты: раскрывать группу в список типов (ссылки P1 продолжают работать, URL длинный) или ввести `group=` (короче, но старые ссылки значат другое).
- Где живёт карта групп: только фронт (`web/lib/`) или `taxonomy.py`. Исследование рекомендует фронт: парсеру группы не нужны.

## Готово когда

Записан ответ: состав групп с числами, судьба `other`, форма чипа «Детям», формат URL и место карты групп. Код заводится отдельным тикетом.

## Answer

Локализация: `grep -rn "EventType = Literal" parser/src/parser/models.py` (22 значения, подтверждено) + чтение `web/lib/urlState.ts`, `web/lib/filters.ts`, `web/components/FilterBar.tsx`, `web/components/CityView.tsx` — 4 места, где живёт нынешняя механика чипов/URL. Отдельно: живой SQL-запрос к Supabase (`events`, город `perm`, будущие) вместо снимка тикета на 19.09 — снимок устарел на 3 дня, счётчики групп пересчитаны от актуальных цифр.

Актуальные числа на 2026-09-22 (Пермь, будущие события, 317 всего):
```
exhibition 80, concert 69, theater 23, other 17, kids 17, education 15, quiz 14,
hobby 13, cinema 12, sport 11, standup 10, science 10, festival 9, business 8,
party 4, art 3, trip 1, food 1
```
`bowling`/`billiards`/`karting`/`quest` — 0 в событиях (площадки, живут в `venues`), в группировку чипов не входят.

**Состав групп** (7 групп + 1 чип-аудитория, в чипы `other` не идёт):

| Группа | Типы | Кол-во |
|---|---|---|
| Музеи и выставки | exhibition, art | 83 |
| Музыка | concert | 69 |
| Лекции и мастер-классы | education, science, hobby, business | 46 |
| Театр и кино | theater, cinema | 35 |
| Квизы, стендап, вечеринки | quiz, standup, party | 28 |
| Спорт и прогулки | sport, trip | 12 |
| Фестивали и праздники | festival | 9 |
| **Детям** (чип-аудитория, не группа) | kids | 17 |
| без чипа | other, food | 18 |

**Судьба `other`.** Убрать из ряда чипов-групп полностью (не переносить в соседнюю группу и не давать своей). События типов `other` и `food` (18 шт., включая `food`=1 — слишком мал для отдельной группы) остаются в общей ленте всегда: чипа-фильтра для них просто нет, из данных ничего не пропадает, они просто не выбираются через ряд групп.

**Форма чипа «Детям».** Только тип `kids` (17), без объединения с тегом «для детей» на событиях других типов (в старом снимке тикета разница была 25 vs 82). Осознанное упрощение для P2: тег как отдельное измерение фильтра — дороже (новый параметр помимо `type=`, новая ветка в `matchesEvent`) и не был запрошен как отдельная задача. Если после P2 окажется мало, это отдельный тикет на тег-фильтр, не блокирует эту группировку.

**Формат URL.** Группа раскрывается в список конкретных типов при клике на чип: `?type=exhibition,art` для «Музеи и выставки», а не новый `?type=museums`/`?group=`. Старые ссылки P1 (`?type=concert`) продолжают работать без изменений — `urlState.ts::parseState/serializeState` не меняются вообще, меняется только источник списка чипов, который показывает `FilterBar`. Цена: URL до 4 типов на одну группу вместо одного идентификатора — приемлемо, раз не трогаем уже работающий контракт с внешними ссылками.

**Место карты групп.** Только фронт, новый файл-константа в `web/lib/` (например `typeGroups.ts`) — маппинг `EventType → группа` и порядок групп в чипах. Парсеру группы не нужны (`taxonomy.py` не трогаем), а частая смена состава групп на UI-уровне не должна требовать миграции БД или синхронизации двух языков.

Код — отдельным тикетом: `web/lib/typeGroups.ts` (карта + список групп), правка `FilterBar.tsx`/`CityView.tsx` на использование групп вместо `typesByFrequency` по отдельным типам, тест на то, что клик по группе пишет в URL ожидаемый список типов.
