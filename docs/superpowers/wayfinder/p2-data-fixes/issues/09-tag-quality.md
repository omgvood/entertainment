# Теги: определения, авто-теги, слияние

Type: grilling
Скилл: superpowers:brainstorming — затрагивает промпты, валидатор и слияние, требует перепарсинга
Status: resolved
Blocked by: 12 (resolved)
Код-тикет: `docs/superpowers/wayfinder/p8-parser-decisions-code/issues/02-tag-quality-code.md`

## Question

Решить, как сделать теги пригодными для сценариев: дать LLM определения тегов, перестать подставлять авто-теги по типу там, где модель ответила пусто, и убрать противоречивые пары при слиянии дублей.

## Контекст

- Промпт даёт только список тегов без определений (`deepseek_extractor.py:63,97`, `groq_extractor.py:74,108`, `gemini_extractor.py:49,82`) — что значит «вечером» или «для пары», модель решает сама.
- `to_event_row` подставляет `default_tags_for_type` при пустых тегах у любого источника (`validator.py:52-54`), а не только у `direct_api`, как говорит комментарий.
- Отсюда ложные теги: авто-тег `concert → вечером` стоит на дневных экскурсиях Пермской оперы (12:00) и дневных концертах филармонии (15:00) — 9 из 13 ошибок «вечером до 17:00».
- Слияние объединяет теги (`merge.py:65-73`): `вечером` + `днём` у 12 событий, `в помещении` + `на улице` у 11.
- Точность по выборкам: «для детей» ≈ 90% (18 из 20), «для пары» ≈ 40–60% (7 из 23 явно ошибочны, ещё 6 — одна кулинарная школа с одинаковым набором тегов).
- Полнота: тег «вечером» покрывает 61% событий с `time_start >= 18:00`, тег «бесплатно» — 25% бесплатных.
- Изменение набора или смысла тегов требует поднять `TAGS_VERSION` и перепарсить (`taxonomy.py:9`).

## Готово когда

Записан ответ: формулировки определений в промпте, условие подстановки авто-тегов, правило слияния противоречивых пар, нужен ли перепарсинг и какие теги вообще остаются в наборе. Код — отдельными тикетами.

## Answer

Локализация: `grep -rn "default_tags_for_type|TAGS_VERSION|ALLOWED_TAGS|filter_tags" parser/src` + `grep -rn "ЗАКРЫТОГО набора" parser/src` — найдено 17 мест (11 код таксономии/validator/merge/models, 6 промпт в трёх экстракторах × 2 вызова). Пути в тикете устарели: `deepseek_extractor.py`, `groq_extractor.py`, `gemini_extractor.py` сейчас лежат в `parser/src/parser/extraction/`, а не в `parser/src/parser/`; содержимое и номера строк (63/98 вместо 63/97) совпадают с описанием тикета почти один в один.

Решение по всем четырём под-вопросам:

1. **Тег «для пары» (40–60% точности).** Добавить в промпт определение, сужающее критерий: `"для пары" — камерное/романтическое мероприятие на двоих (свидание), не для компании и не для семьи с детьми`. Остальные 10 тегов не трогаем — измеренной проблемы точности нет только у «для пары» и «для детей» (у последней и так ≈90%), переписывать весь набор без данных было бы решением без факта. Формулировки для промпта — задача тикета на код.
2. **Условие подстановки авто-тегов (`TYPE_DEFAULT_TAGS`).** Только для `direct_api`-источников (twogis-*, timepad, quizplease — `extraction_mode: direct_api` в `seeds.yaml`), не для всех источников с пустыми тегами, как сейчас. Комментарий в `validator.py:81` уже утверждает это поведение — код ему не соответствует, это баг, не документация. Признак в коде есть готовый: `SOCIAL_SOURCE_PREFIXES = ("vk-", "telegram-", "generic")` (`config.py:28`) уже используется тем же способом в `is_spurious_always`/`is_non_event` — условие в `to_event_row` должно стать `not any(source.startswith(p) for p in SOCIAL_SOURCE_PREFIXES)`. LLM-источники (VK/TG/generic) с пустыми тегами получают `tags=[]` — пустой список честнее неверного авто-тега (9 из 13 ошибок «вечером» в тикете — как раз авто-тег `concert → вечером` не на direct_api).
3. **Слияние противоречивых пар (`merge.py::_enrich`).** При конфликте побеждает тег строки-победителя (той, что выбрана по `priority`), конфликтующий тег проигравшего в объединение не попадает — остальные его теги без конфликта объединяются как сейчас. Противоречащие пары: `{("вечером","днём"), ("в помещении","на улице")}`. Обоснование: победитель уже выбран как более надёжный источник факта в других полях (`_priority`) — тот же принцип для тегов, не смешивание с проигравшим.
4. **Перепарсинг.** Да — поднять `TAGS_VERSION` (`taxonomy.py:9`) и перепарсить после того, как правки промпта и условия авто-тегов попадут в код. Без перепарсинга старые галлюцинации (в т.ч. 9/13 «вечером») останутся в БД неопределённо долго.

Код — отдельным тикетом: правка промпта (3 файла × 2 места), условие в `validator.py:82-83`, правило конфликта в `merge.py:65-73`, `TAGS_VERSION` + перепарсинг.
