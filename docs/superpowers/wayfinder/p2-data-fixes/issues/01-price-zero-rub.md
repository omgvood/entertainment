# Цена: `0 ₽` больше не «бесплатно»

Type: task
Скилл: superpowers:test-driven-development — тест в `price.test.ts` пишется первым и падает
Status: open
Blocked by: —
Ветка: `fix/price-zero-rub` от `master`

Описание расписано подробно 2026-09-20, чтобы работу можно было начать в новом чате, не поднимая переписку: ниже всё, что нужно — код с номерами строк, запросы вместо чисел, что проверить у источника до правки и чем заканчивается сессия.

## Question

`web/lib/price.ts:15` считает бесплатными строки `0 ₽` и `от 0 ₽`. LLM пишет их, когда цены не знает, — на 2026-09-20 это **66 будущих событий Перми**, которые ложно значатся бесплатными: занятия Пермской галереи, матчи Кубка «Урал-Грейта», циклы для подростков. Убрать из `FREE_RE` ветки с нулём, оставив словесные признаки («бесплатн / вход свободн / свободный вход»).

## Что в коде сейчас

```ts
// web/lib/price.ts:15
const FREE_RE = /бесплатн|вход свободн|свободный вход|^0\s*₽|^от 0\s*₽|^0$/i;

// web/lib/price.ts:19-22
export function priceKind(event: Pick<EventItem, "priceMax" | "priceText">): PriceKind {
  if (event.priceMax > 0) return "known";
  return FREE_RE.test(event.priceText ?? "") ? "free" : "unknown";
}
```

**Правка — удалить три ветки с нулём** (`^0\s*₽`, `^от 0\s*₽`, `^0$`), больше в этом файле ничего не трогать. `price_min`/`price_max` не затрагиваются — правило только про смысл строки.

**Существующие тесты придётся перенести, а не дополнить.** В `web/lib/price.test.ts:14-15` строки `"0 ₽"` и `"От 0 ₽"` стоят в списке «считает бесплатным». Они переезжают в список `unknown` на строке 20. Это и есть падающий тест по TDD: перенести первым, увидеть красное, потом править регексп.

**Кто зависит от `priceKind`** — два потребителя, оба меняют поведение:

- `web/lib/filters.ts:87` — фильтр цены пропускает проверку диапазона, если вид `unknown`. Сегодня событие с `0 ₽` при `pmin > 0` молча прячется как бесплатное; после правки будет показываться всегда. Это цель правки, а не побочный эффект.
- `web/lib/search.ts:67` — событию вида `free` в поисковый документ дописывается `"бесплатно free вход свободный"`. После правки 66 событий перестанут находиться по запросу «бесплатно» — и правильно, потому что бесплатность у них не подтверждена.

Карточка (`web/components/EventCard.tsx:87`) и страница события печатают `priceText` как есть — там ничего не изменится.

## Цифры: запросы, а не числа

Решение журнала от 2026-09-20: в тикете живёт SQL, число — только датированный снимок. Прогнать в начале сессии (Supabase MCP, только чтение) и сверить с тем, что ниже.

```sql
-- Доли видов цены по будущим событиям Перми (повторяет логику priceKind)
WITH perm AS (
  SELECT * FROM events WHERE city='perm' AND date::date >= CURRENT_DATE
), k AS (
  SELECT
    (price_max > 0) AS is_known,
    (coalesce(price_text,'') ~* 'бесплатн|вход свободн|свободный вход') AS words,
    (coalesce(price_text,'') ~* '^0[[:space:]]*₽|^от 0[[:space:]]*₽|^0$') AS zero_branch
  FROM perm
)
SELECT
  count(*) AS perm_future,
  count(*) FILTER (WHERE is_known) AS known,
  count(*) FILTER (WHERE NOT is_known AND (words OR zero_branch)) AS free_now,
  count(*) FILTER (WHERE NOT is_known AND NOT (words OR zero_branch)) AS unknown_now,
  count(*) FILTER (WHERE NOT is_known AND zero_branch AND NOT words) AS flips_to_unknown,
  count(*) FILTER (WHERE NOT is_known AND coalesce(price_text,'') ~* '^0$') AS bare_zero
FROM k;
```

Снимок на 2026-09-20 (после миграции тикета 03): `perm_future` 372, `known` 95, `free_now` 193 (52%), `unknown_now` 84 (23%), `flips_to_unknown` **66**, `bare_zero` **0**.

После правки: free 127 (34%), unknown 150 (40%), known 95 (26%).

```sql
-- Что именно перестанет быть «бесплатным» — список для глазной проверки
SELECT title, price_text, date, source FROM events
WHERE city='perm' AND date::date >= CURRENT_DATE AND price_max = 0
  AND coalesce(price_text,'') ~* '^0[[:space:]]*₽|^от 0[[:space:]]*₽'
ORDER BY date;
```

Примеры из этого списка на 2026-09-20: «Семейные мастер-классы „Идём в музей!“» (`0 ₽`), «Финал Кубка „Урал-Грейта“» (`от 0 ₽`), «Пермская деревянная скульптура» (`0 ₽`), «Цикл занятий „Фотография как искусство“ для подростков 12-16 лет» (`0 ₽`).

`^0$` — мёртвая ветка: `bare_zero` = 0, ни одна строка в Перми под неё не подходит. Удаляется заодно, поведение не меняет.

## Ресерч до правки

Утверждение «`0 ₽` значит „цену не знаем“» держится на выборке примеров. Проверить на трёх событиях из списка выше, прежде чем менять код:

1. Взять событие с `0 ₽` у площадки с известным прайсом — например «Пермская деревянная скульптура» (Пермская художественная галерея).
2. Открыть страницу события или площадки в источнике (`source` есть в запросе выше) и найти цену.
3. Записать в `## Answer`: три строки вида «событие — что в БД — что у источника».

Ожидаемый результат — цена у источника есть и она не нулевая, то есть `0 ₽` действительно означает незнание. **Если окажется наоборот** (часть событий вправду бесплатна и `0 ₽` — честный ноль) — правка становится спорной, её нужно остановить и вынести в тикет 08 вместе с решением по схеме, а не продавливать.

Глубокая версия этой проверки — отдельный тикет 10 «Проверка „бесплатно“ по источникам», он в бэклоге и держит тикет 08. Здесь нужны только три примера, чтобы не менять поведение вслепую.
