Type: task
Status: open
Blocked by: —
Ветка: работа в `master` (пуш) плюс запись в БД

## Question

Код фильтра не-событий уже в локальном `master` (`1eaab55`, `b043ef4`, `91e68b2`, `0ed2466`, `7c43fd9`), но миграция `20260918000001_remove_non_events_social.sql` к БД не применена, а сам `master` не запушен. Из-за первого в выдаче висят новости и реклама, из-за второго живой сайт собирается со старого `origin/master`.

## Контекст

- Проверено 2026-09-20: 13 строк из списка миграции лежат в `events`, 12 из них — будущие события Перми с `type='other'`.
- После применения: `other` в Перми 37 → 25, всего будущих 359 → 347, хвост 2027–2028 почти исчезает, у Сочи не остаётся ни одного будущего события.
- `origin/master` отстаёт на 16 коммитов: кроме фильтра не-событий там вся реализация P1 (лента дат, серии, чипы, URL, «Другие даты»). Живой сайт https://entertainment-eta.vercel.app/perm всего этого ещё не показывает.
- Фильтр ловит не всё: «Проверка школьников на склонность к суицидальному поведению» (01.10) в списке нет и предикатом не ловится.
- Запись в БД и пуш — необратимые действия, каждое с отдельного согласия пользователя.

## Готово когда

- Миграция применена, проверка из её хвоста возвращает 0 строк.
- `master` запушен, сборка Vercel прошла, на живом сайте видна лента дат.
- В ответ тикета записано: сколько строк удалено, каким стал `other` и общее число будущих событий.
