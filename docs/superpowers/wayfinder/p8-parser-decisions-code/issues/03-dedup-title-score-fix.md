## Question

## Контекст

- Фикс закрывает только первую группу (6/19): не применять `_venue_factor` при `title_score == 1.0`, не поднимать общий порог — иначе заденет «Балетный квартал» (его `title_score` физически не превышает 0.842).
- Локализация p2/14: скорер `parser/src/parser/fuzzy.py`, пороги `parser/src/parser/config.py:36-40` (`DEDUP_MERGE_SCORE=0.95`, `DEDUP_CANDIDATE_SCORE=0.75`), запись в БД `parser/src/parser/db.py:440-474`. Повторный грep 2026-09-22 подтвердил `fuzzy.py::score_pair` (строка объявления ~153) и `_venue_factor` (~140).

## Answer

**Правило сужено относительно p2/14: при `title_score == 1.0` не штрафуется только средняя полоса площадки (`venue_score` в (0.3, 0.6], множитель 0.85 → 1.0). Площадка с `venue_score` ≤ 0.3 по-прежнему ×0.5.** Согласовано с пользователем в сессии 2026-09-29.

Причина — локализация нашла тест, который p2/14 не видел: `test_fuzzy.py::test_score_pair_different_venue_cuts_score` (Dedup v2, `afb8a1f`) кодирует «одинаковое название на разных площадках — разные события» («Стендап-концерт» в «Бар Заря» / «Клуб Пилот», одно время; `venue_score` 0.222). Буквальное правило p2/14 перевело бы его в `auto_merge`. Кроме того, p2/14 смотрел только `dedup_candidates` (score ≥ 0.75): пары `title 1.0 × 0.5 = 0.5` туда не пишутся, и сколько их начало бы сливаться при полном снятии множителя — неизвестно. Все пары группы 1 из p2/14 (`venue_score` 0.33–0.51) и обе живые пары на 2026-09-29 (0.40, 0.529) в суженное правило попадают — решение p2/14 по данным выполнено полностью.

`title_score == 1.0` включает вложенность («Спектакль «X»» ⊃ «X»), как и предполагал p2/14. `score_without_containment` получает тот же множитель — рёбра-вложенности по-прежнему проходят проверку зонтичных заголовков в `cluster_events`.

Тесты (`test_fuzzy.py`, шов — `score_pair`): обе живые пары группы 1 → `>= MERGE` (красный до правки: 0.85); «Балетный квартал» с максимальным `title_score` 0.842 → в диапазоне `[CANDIDATE, MERGE)` (регресс-страж, зелёный сразу); тест про стендап не тронут. `pytest` — 306 passed.

Переклассификация — на следующем ежедневном прогоне (TTL `dedup_candidates` 1 день), бэкфилл не нужен.

Локализация: `grep -rn "score_pair\|_venue_factor\|DEDUP_MERGE_SCORE\|DEDUP_CANDIDATE_SCORE" --include=*.py parser/` + `grep -rn "title_score\|Балетный квартал" --include=*.py parser/` + SQL по `dedup_candidates`, найдено 12 мест (`fuzzy.py` ×3, `merge.py:193`, `pipeline.py:384`, `cli.py:598`, `config.py:36-39`, `db.py:463`, `test_fuzzy.py` ×2 — в т.ч. `different_venue_cuts_score`, не названный в тикете, — `test_permopera.py:51`, `test_merge.py`/`test_db.py`/`test_pipeline_warnings.py` через `cluster_events`) — менялись 2 (`fuzzy.py`, `test_fuzzy.py`).
Расхождения цифр: да — пар с `title_score == 1.000` сейчас 2, а не 6 (таблица пересчитывается ежедневно); всего `candidate` 14, а не 19, из них «Балетный квартал» 7.

- **Проверено на проде 2026-10-03:** по `dedup_candidates` с `last_seen_at > 2026-09-29 20:00 UTC` пары «Музейный Олимп» (venue_score 0.400) и «Хроникер» (0.529) — `auto_merge`. `candidate` 11 (было 14), `auto_merge` 48 — остаток не вырос, вопрос о разрешателе не возвращается.
