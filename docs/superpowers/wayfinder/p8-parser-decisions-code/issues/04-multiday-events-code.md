## Question

Решение «Многодневные события: дата начала и конца» принято 2026-09-22 (карта p2, тикет 15): не заводить колонку `date_end`, а разворачивать диапазон в парсере в одну `EventRow` на каждый день (тот же паттерн, что уже применяется к выставкам). Тикет на код не заведён. На `master` 2026-09-22 фестивали по-прежнему лежат одной строкой на дату начала и исчезают из ленты со второго дня.

## Контекст

- Решение: `docs/superpowers/wayfinder/p2-data-fixes/issues/15-multiday-events.md`, `## Answer`. Пять пунктов:
  1. Никакой новой колонки в схеме — диапазон существует только на входе в парсер.
  2. LLM-промпт получает второе поле `date_end` (по умолчанию равно `date_start` для однодневных — обратная совместимость без миграции старых источников). Парсер (в `to_event_row` или на шаг раньше) разворачивает `[date_start, date_end]` в список дат, создаёт по строке `EventRow` на каждую.
  3. Граница разворачивания — 21 день; диапазон длиннее — сигнал ошибки LLM (спутала фестиваль с сезоном), остаётся одна строка на `date_start`, в лог — warning.
  4. Бэкфилл не нужен — уже записанные фестивали доберут дни на следующем ежедневном прогоне через upsert по новому slug каждого дня, не трогая существующую строку.
  5. Фронт не меняется — `web/lib/series.ts::otherDates` уже группирует события по title+venueName и схлопывает в «ещё N дат», механизм подхватит многодневные события автоматически, как уже подхватывает выставки.
- Локализация p2/15 (парсер): `parser/src/parser/models.py:33,69,77,130` (схема и валидатор — даты) — перепроверить точные строки перед правкой, модель могла измениться после 2026-09-20.
- Локализация p2/15 (фронт, не трогать в этом тикете, но не сломать): `web/lib/eventTiming.ts`, `web/components/EventCard.tsx`, `web/components/CityView.tsx`, `web/lib/series.ts`, `web/lib/series.test.ts`, `app/{sochi,perm}/events/[slug]/page.tsx`, `web/lib/search.ts`.
- Этот тикет намеренно идёт после тикета 02 этой карты (теги) в очереди волн — оба правят один и тот же набор из трёх файлов экстракторов (`deepseek_extractor.py`, `groq_extractor.py`, `gemini_extractor.py`), параллельная работа рискует конфликтом промпта.
- Тикет 06 карты p2 («идёт сейчас») уже учёл многодневные события как обычный набор строк по датам — отдельного случая политика не требует, ничего в 06 менять не нужно.
