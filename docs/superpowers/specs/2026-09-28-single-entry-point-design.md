# Единая точка входа в сессию

Дата: 2026-09-28. Путь brainstorming: architectural.

## Зачем

Пользователь хочет открывать любую сессию одним файлом — `docs/superpowers/wayfinder/_next-session.md` — без пояснений. Сейчас процесс описан в пяти местах, и они расходятся:

| Где | Что | Расхождение на 2026-09-28 |
|---|---|---|
| `CLAUDE.md` → `docs/agents/*` | действующие правила R-01…R-11, последовательность, шаблон открытия чата | эталон |
| `_next-session.md` | промпт следующей сессии | не трекается; правка шага 7 в `session-protocol.md`, которая его вводит, не закоммичена |
| Obsidian `Журнал проблем.md` (вне git) | копия журнала | застыла на INC-08 / R-06, в репозитории INC-15 / R-11 |
| Obsidian `Сценарии работы.md` (вне git) | три сценария, handoff в `%TEMP%` | на «Сценарий 1» ссылается `skills-routing.md:10` — ссылка наружу git (R-06) |
| Память агента | `wave2-plan`, `wave-rule`, `wayfinder-ticket-workflow`, `process-journal` | `wave2-plan` устарел, `process-journal` указывает на копию в Obsidian, остальное дублирует `session-protocol.md` |

Шаблон открытия чата по тикету существует в трёх копиях: одна в репозитории (`session-protocol.md`), две в Obsidian (`Журнал проблем.md`, `Сценарии работы.md`).

## Решения, принятые с пользователем

- **Источник истины — только репозиторий.** Obsidian — указатель и архив.
- **Вход — всегда `_next-session.md`.** Внеплановая задача подаётся тем же файлом плюс фраза «вместо этого: <симптом>».
- **Процессные записи памяти сжимаются до одного указателя.**
- **Вариант C:** тонкий `_next-session.md` (изменчивое) + постоянный раздел «Вход в сессию» в `session-protocol.md` + одна строка в `CLAUDE.md`.

## Готово когда

Любая сессия — тикет, сведение, внеплановое — стартует с одного `_next-session.md`; у каждого факта процесса один источник в репозитории, остальные места на него ссылаются; проверки из раздела «Проверка» проходят.

## Вне рамок

Само сведение по p4–p8 и превышение R-05 (11 open-тикетов при лимите 3) — это работа следующей сессии. Содержимое тикетов. Предметные записи памяти (VK, Timepad, Vercel и т. п.). `docs/research/2026-09-24-site-audit.md` — вопрос о его коммите задан шагом 0 следующей сессии.

## Дизайн

### 1. `_next-session.md` — только изменчивое

Трекается в git. Переписывается на шаге 7 отдельным docs-коммитом в `master`; внутри ветки тикета не правится. Четыре блока:

```
# Следующая сессия
Обновлено: <дата> — <после чего>. Протокол входа: docs/agents/session-protocol.md §«Вход в сессию».

## Базовая линия      — master = <hash>; pytest N passed; vitest M passed
## Следующий шаг      — тип (тикет / сведение / аудит волны), путь к тикету или карте, скилл, «Готово когда» одной строкой
## Стоп-условия       — только специфичные для шага; общие — в протоколе
## Отложено           — пусто или «внеплановое, заведено в <тикет>, ждёт сведения»
```

В файле нет команд R-01, шаблона открытия чата, правил про пуш и `## Answer` — только ссылка на протокол. Текущее содержание (сведение, шаги 0–4) переносится в эту форму без изменения сути.

«Отложено» не даёт плану потеряться, когда внеплановая задача его вытеснила.

### 2. `session-protocol.md` §«Вход в сессию» — постоянное

Новый раздел в начале файла, до R-01:

1. **Сверка R-01**: три git-команды и сравнение с «Базовой линией» `_next-session.md`. Расхождение — стоп и вопрос.
2. **Развилка.**
   - На входе только файл → выполняется «Следующий шаг».
   - Файл + «вместо этого: <симптом>» → внеплановая ветка: локализация по R-02, ноль правок кода, результат — тикет `Status: backlog` в подходящей карте по `_ticket-template.md`. Подходящей карты нет — вопрос пользователю (новая карта только с его согласия). Затем вопрос: брать тикет сейчас (вытесняет план, план уходит в «Отложено») или оставить до сведения.
3. **Три сценария** из Obsidian `Сценарии работы.md`, сжатые до таблицы «сценарий → скилл → чем заканчивается»: тикет из волны; внеплановое; исследование → сведение. Дерево «с чего начать» не переносится — его заменяет развилка.
4. **Шаблон открытия чата по тикету** — переносится сюда из конца файла. Копии в Obsidian уходят в архив вместе со своими файлами (раздел 3); в репозитории копия и так одна.
5. **Выход**: `## Answer` → строка в карте → PR → после мерджа уборка (R-04) → переписать `_next-session.md`.

**Handoff-файл упраздняется.** Root cause, неудачные попытки и варианты решения ложатся в разделы шаблона тикета `Question` / `Контекст` / `Кто зависит`; результат внеплановой ветки — сразу тикет. `skills-routing.md:10` меняется соответственно. Упоминания HANDOFF в закрытой карте p3 и в журнале не трогаются — это история.

### 4. Проверка

Тестов на документы нет — проверка командами:

1. **R-06**: каждый путь в обратных кавычках из `CLAUDE.md`, `skills-routing.md`, `session-protocol.md`, `_next-session.md` существует (`test -e`) или помечен «вне git».
2. **Шаблон в одной копии**: `grep -rl "Отметь, какую ветку" docs/agents docs/superpowers/wayfinder CLAUDE.md` → один файл, `docs/agents/session-protocol.md`.
3. **Нет ссылок наружу**: `grep -n "Сценарий 1\|HANDOFF\|(temp)" docs/agents/session-protocol.md docs/agents/skills-routing.md` → пусто.
4. **Журнал в репо полнее Obsidian-копии**: каждый `INC-NN` и `R-NN` из `Журнал проблем.md` есть в `process-journal.md`. Проверяется **до** пометки архивом; недостающий ID — стоп и вопрос.
5. **Живой прогон**: следующая сессия (сведение) открывается одним `_next-session.md` без пояснений; признак успеха — первый ответ начинается с вывода сверки R-01. Результат фиксирует сама эта сессия.
