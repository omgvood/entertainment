# Fuzzy-дедуп (Dedup v2) — спека

## Контекст и решения

### Проблема

Ключ карточки — `id = city + slug`, где `slug = транслит(title) + date`. Два источника (или два поста в одном источнике) с разной формулировкой одного анонса дают разные `id` → две карточки. `merge.py` схлопывает только точные совпадения `id`; `near_misses` (та же площадка+дата, разные названия) считаются, но не используются.

### Что показали данные прода (643 события, 7 источников, Пермь)

98 групп «площадка+дата» с более чем одной карточкой. Выборка 60 пар:

- Настоящие дубли почти все **внутри одного источника** `vk-posts`, а не между Timepad и VK: «День рождения парка Горького» / «Парку Горького — 222 года!» / «Праздник "Парку Горького — 222 года!"» / «День рождения парка имени Горького — 222 года» — 4 карточки; «День открытых дверей в Автопрестиж» ×3; «Акция "Собака Обнимака"» ×2. Кросс-источниковый дубль в выборке один: ПЕРММ 18.08, telegram×2 + vk.
- Ложных пар (та же площадка+дата, разные события) много: планетарий — 4 сеанса, худгалерея — 3 экскурсии, Gastro.Li — «Квиз, плиз!» 15:00 vs «[ностальжи]» 18:00.
- **`time_start` разделяет их почти идеально:** у настоящих дублей время совпадает или пусто, у ложных различается. Единственное исключение — «Мастер-класс «Единорог»» vs «Мастер-класс «Планета»» (оба 12:00), и его отсекает сходство названий.

### Принятые решения

| Решение | Выбор | Почему |
|---|---|---|
| Скоуп | Все пары в пределах `city+date`, независимо от `source` | Основной объём дублей — внутри `vk-posts` |
| Судьба дубля | Write-time guard: новая строка не создаётся | Не ломает URL, не требует правок фронта |
| Серая зона 0.75–0.95 | Только наблюдение (таблица `dedup_candidates`) | Ревью-инструмента нет и не нужен, пока нет данных о калибровке |
| Накопленные дубли | Разовая CLI `dedup-backfill` с `--apply` | Осознанное удаление под просмотром человека; риск 404 принят |
| Транзитивность | Union-find, компоненты связности | Кластер парка Горького ×4 попарным мержем не разгрести |
| Метрика | `max(char_ratio, containment, jaccard)` | Каждая ловит свой тип дубля (см. таблицу ниже) |
| Площадка | Мультипликативный штраф, пустая = нейтрально | Venue не должен помогать, только уметь навредить |
| LLM-арбитр | Отложен | Уже записанные события им не починить без `merged_into`/удаления; таблица кандидатов копит материал для будущего решения |

### Формула

```
блокировка: сравниваем только пары с одинаковыми city и date; date='always' исключены

если обе time_start заданы и различаются      → score = 0        (жёсткий guard)
title = max(char_ratio, containment, jaccard)
score = title × venue_factor
если подтверждающего сигнала нет вовсе        → score × 0.9
```

`venue_factor`: `1.0` если venue пуст хотя бы у одного (нейтрально) или сходство > 0.6; `0.85` при 0.3–0.6; `0.5` ниже 0.3.
«Подтверждающего сигнала нет вовсе» = venue пуст хотя бы у одного **и** time пуст хотя бы у одного. Это чуть строже формулировки «пусто у обоих»: если у одной строки площадка есть, а у другой нет, подтверждения всё равно не было.

| Метрика | Какой дубль ловит |
|---|---|
| `SequenceMatcher` по нормализованной строке и по ней же без пробелов | «аудио спектакль-променад» vs «аудиоспектакль-променад» |
| containment `\|A∩B\| / min(\|A\|,\|B\|)` | «Акция X» ⊂ «АКЦИЯ X: ПОДРОБНОСТИ» |
| Jaccard | перестановки слов |

Containment засчитывается, только если у короткого заголовка **≥2 значимых токена и ≥12 символов** — иначе «Йога» схлопнется с «Йога на набережной». При срабатывании guard'а containment не обнуляет пару, а просто выбывает из `max(...)`.

**Пороги:** `≥0.95` — auto-merge, `0.75–0.95` — запись в `dedup_candidates` без слияния, ниже — врозь.

**Известный предел:** кластер «День рождения парка Горького» ×4 правила не поймают (общих основ 2 из 6 → ~0.33). Он останется четырьмя карточками и всплывёт только в `dedup-backfill` с пониженным порогом. Это осознанная цена отказа от LLM-арбитра.

### Семантика write-time guard

Ежедневный пайплайн умеет ровно одно — **не создавать новый `id`**. Отсюда правила на кластер:

- есть и записанные, и новые строки → новые выбывают, их поля дозаполняют победителя из записанных;
- только новые → победитель по `priority`, проигравшие выбывают;
- только записанные → **ничего не делаем** (обе карточки уже в БД, выбрасывание из upsert их не удалит, а только сделает данные несвежими). Пара уходит в `dedup_candidates` — это работа для `dedup-backfill`.
