# Лента дат и серии событий — спецификация

Дата: 2026-09-19. Реализация — план `docs/superpowers/plans/2026-09-19-feed-date-strip-series.md`.

## Контекст

UX-разбор `/perm` 2026-09-19 показал:
- клик по чипу «Концерт» **убирал** концерты — по умолчанию были выбраны все типы
  (`DEFAULT_FILTERS.types = new Set(ALL_TYPES)`), клик снимал выделение с одного типа
  вместо того, чтобы оставить только его;
- 423 карточки на одной странице, из них одинаковые повторы (выставка «Пермская
  деревянная скульптура» — 13 раз, одна на каждую дату);
- фильтры теряются при возврате со страницы события на главную;
- дорогие события (>5000 ₽) молча скрывались фильтром цены — верхняя граница была
  зашита в `DEFAULT_FILTERS`, а не в URL/UI.

Замер: схлопывание повторов в серии даёт −19% карточек (423 → 341). Основное сокращение
даёт лента дат: по умолчанию показывается один день (20–60 серий вместо 341).

Выбранный объём — P0+P1 без мобильной вёрстки (вынесена в роадмап README, пункт 19) и
подход A: группировка серий на клиенте по ключу «нормализованное название | площадка».
Схема БД и парсер не меняются.

## 1. Модель серий

Одно и то же событие (выставка, регулярная экскурсия, спектакль на гастролях) лежит в
БД отдельной строкой на каждую дату/сеанс. Чтобы лента показывала его одной карточкой,
события группируются в серии на клиенте, в момент рендера — не в БД и не в парсере.

**Ключ серии** — `normalize(title без возрастной метки) | normalize(venueName)`
(`lib/series.ts:seriesKey`). Возрастные метки (`6+`, `(12+)`) вырезаются перед
нормализацией: один и тот же спектакль приходит из разных источников с меткой и без.
Ключ консервативный: «Пермская галерея» и «Пермская художественная галерея» не
склеиваются — лишняя карточка безобиднее, чем слияние разных событий (тот же принцип,
что в fuzzy-дедупе парсера).

**Серия** — `{ key, events }`, `events` отсортированы по дате и времени начала
(`compareByDateTime`: сначала дата, потом `timeStart`, событие без времени — в конец
своего дня). Порядок серий на выходе `groupSeries` — порядок первого появления ключа во
входном массиве; для поиска это порядок релевантности.

**Карточка серии** показывает один сеанс (`shown`, выбирается фильтрами дат/типа/цены,
см. раздел 2) и подпись «ещё N дат до …», если у серии есть другие **различные даты**
(`otherDates`; несколько сеансов в один день не увеличивают счётчик).

## 2. Лента дат и фильтры

**Лента дат** (`lib/dateStrip.ts`, компонент `DateStrip`) — горизontальный список:
Сегодня · Завтра · Выходные · 12 отдельных дней подряд · Все даты. Каждый пункт
показывает число серий, попадающих в него при текущих фильтрах типа/цены; пустые дни
приглушены и недоступны для клика (кроме уже выбранного).

Дата — первое решение пользователя, поэтому лента всегда на виду, а выдача по умолчанию
показывает один день, а не всю афишу на месяц (как было — «Сегодня / Завтра / Дальше»).
Раньше секции «Сегодня»/«Завтра» на главной не зависели от переключателя «Когда» — это
было задокументированное решение ([README.md:1925](../../../README.md)), не ошибка.
Лента дат заменяет всю эту схему целиком: «Когда» из `FilterBar` убирается, единственный
выбор дня — по ленте.

**Выбор дня по умолчанию** (`autoDate`): первый день ленты, где есть события
(`firstNonEmptyDay`), если сегодня пусто — «Все даты», если пусто вообще всё. Выбор
фиксируется один раз при заходе (после чтения URL), чтобы смена типа/цены не
перескакивала на другой день молча.

**Фильтры** (`lib/filters.ts`):
- `types: ReadonlySet<EventType>` — пустой набор означает «все типы» (было: полный набор
  по умолчанию, и клик по чипу его уменьшал — это и было багом «клик убирает тип»).
  Клик по чипу при пустом наборе добавляет **только** этот тип.
- `priceMin: number`, `priceMax: number | null` — `null` означает «без верхней границы»
  (было: числовой потолок в `DEFAULT_FILTERS`, скрывавший дорогие события по умолчанию).
- `date: DateSel | null` — `null` означает «использовать `autoDate`»; в URL не пишется.

`matchesEvent` проверяет тип и цену. Событие с неизвестной ценой (`priceKind !==
"known"`, т.е. «по билетам», «Уточняйте») **всегда** проходит фильтр цены: в БД
неизвестная цена неотличима от нуля, и прятать карточку из-за пробела в данных хуже, чем
показать её.

`inDateSel` проверяет попадание даты события в выбор ленты: `today`/`tomorrow` — от
`getCityToday`; `weekend` — ближайшие Сб и Вс **включая сегодня**; конкретный день —
точное совпадение; `all` — всегда true. Правило для «Выходные»: если сегодня
воскресенье, выходные — это только сегодня, а не сегодня + следующая субботавоскресенье
(старая реализация раньше захватывала следующую субботу).

`visibleSeries` для каждой серии берёт первый сеанс, прошедший **и** фильтры типа/цены,
**и** выбор даты — не первый сеанс серии по датам вообще. Так у серии с дешёвым будним и
дорогим выходным сеансом при фильтре цены показывается подходящий сеанс, а не первый по
дате.

## 3. Состояние в URL

Параметры: `?date=&type=&pmin=&pmax=&q=` (`lib/urlState.ts`). Значения, равные
умолчанию, в URL не пишутся — короткий URL для типичного случая. `type` — список через
запятую в порядке `ALL_TYPES` (не в порядке кликов), чтобы строка не зависела от того,
в каком порядке пользователь щёлкал чипы.

**Разбор** (`parseState`) отбрасывает всё, что не может быть безопасно применено, и
откатывается к умолчанию по каждому полю независимо:
- `date`: именованные значения (`today`/`tomorrow`/`weekend`/`all`) или `YYYY-MM-DD` не
  раньше `today` — иначе `null`. Дата из прошлого, несуществующая (`2026-02-30`,
  `2026-13-45`) или произвольный мусор в старой/битой ссылке не должны ронять страницу —
  она просто открывается в состоянии по умолчанию.
- `type`: неизвестные значения молча выбрасываются из списка.
- `pmin`/`pmax`: нечисловые или отрицательные значения — умолчание.

Состояние читается **только на клиенте**, после монтирования: статический HTML один на
все query-строки (SSG), `useSearchParams()` требует `<Suspense>` и увёл бы страницу из
чистого SSG.

**Запись** синхронная для дискретных действий (клик по фильтру/ленте дат) и с задержкой
300 мс для набора текста в поиске — так «Назад» браузера не отматывает каждый символ, но
клик по фильтру не теряется, даже если сразу после него произошёл переход на страницу
события. Пишется через `history.replaceState` (не `pushState` — иначе «Назад» отматывал
бы каждый клик по фильтру) и параллельно в `sessionStorage["afisha:list:{city}"]`
(`listStateKey`), которую читает страница события для ссылки «← Все события». Каждое
обращение к `sessionStorage` — в `try/catch`: в приватном режиме хранилище может быть
недоступно, это не должно ронять страницу — ссылка просто ведёт на `/{city}` без
фильтров.

## 4. «Другие даты» на странице события

Страница события показывает сиблингов серии — остальные сеансы с тем же `seriesKey`, из
всех событий города на момент сборки (мемоизировано на билд одним запросом на город,
`getSeriesSiblings`). Блок `OtherDates` группирует сиблингов + текущее событие по дате
(`groupByDate`) и показывает список дней с временем сеансов; у текущего дня-времени —
пометка «эта дата» вместо ссылки. Если сиблингов нет, блок не рендерится.

Ссылка «← Все события» (`BackLink`) читает `sessionStorage["afisha:list:{city}"]` и ведёт
на `/{city}` с этой строкой запроса — так фильтры и выбранный день не теряются при
переходе со страницы события назад. Прямой заход на страницу события (нет записи в
`sessionStorage`) — ссылка ведёт на `/{city}` без параметров.

## 5. Тестирование

Юнит-тесты — только по чистым функциям в `lib/`, Vitest, окружение node (без jsdom):
`dateUtil`, `series`, `filters` (переписан), `dateStrip`, `urlState`. Компоненты
(`DateStrip`, `EventCard`, `CityView`, `FilterBar`, `OtherDates`, `BackLink`) не
покрываются автотестами — тестового фреймворка для компонентов проект не вводит;
проверяются вручную в превью (`preview_start`) по чек-листам задач 6b и 7 плана.

Не проверяется вживую и фиксируется в отчёте как покрытое только тестом/чтением кода:
- поведение при устаревшей сборке (`today` из пропа — вчерашний день) — тест
  `getCityToday` плюс чтение кода `CityView` (пересчёт `today` на клиенте после
  монтирования, фильтрация `liveEvents` по свежему `today`);
- переиспользование мемоизации `getSeriesSiblings` между страницами при `next build` —
  видно только косвенно, по времени сборки.

## Готово

- Лента дат заменяет секции «Сегодня / Завтра / Дальше»; по умолчанию открыт один день.
- Повторы одного события на разные даты схлопнуты в одну карточку серии с «ещё N дат».
- Чипы типов: пустой выбор = все типы, клик оставляет только выбранный, есть «×
  Сбросить».
- Верхней границы цены по умолчанию нет; поле «максимум» принимает пустое значение.
- «Выходные» корректны в воскресенье (только сегодня, не захватывают следующую субботу).
- Состояние (дата/типы/цена/поиск) — в URL и в `sessionStorage`; переход на страницу
  события и обратно не теряет фильтры.
- Страница события показывает «Другие даты» серии.
